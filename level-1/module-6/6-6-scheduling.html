6.6 Scheduling and time-based logic

In one line

Schedules decide when plant should run; timers and time-based logic decide how it changes state — and together they are the biggest single energy saving a BMS delivers.

?Why it matters

Plant that runs when nobody is there wastes energy every night and weekend. Plant that starts too late leaves the first people of the day uncomfortable. Getting schedules, holidays and overrides right — and making sure they live in the controller — is basic, valuable BMS work.

⚙How it works

Schedules and calendars

ElementWhat it doesBACnet object
Weekly scheduleOn/off (or mode) times for each day of the weekSchedule — weekly part
Exception scheduleDifferent times for specific datesSchedule — exception part
Holiday calendarList of dates treated as holidays by many schedulesCalendar
Schedule outputWrites occupied/unoccupied to the plant's occupancy pointWrites to a BV / MSV at a set priority

Schedules must run in the controller (or a supervisory controller on the same network), so plant still starts and stops when the server is down. The server is where people view and edit them.

Occupancy modes

ModeTypical behaviour
OccupiedNormal setpoints, full ventilation
UnoccupiedPlant off; may restart for humidity or temperature limits
StandbyPlant on with wider setpoints (e.g. empty meeting room)
Optimum startPlant starts early enough to reach setpoint at occupancy

Optimum start

Instead of a fixed early start, the controller works out when to start: it compares the room temperature with the setpoint and uses the pull-down rate it has learned on previous days. Example: return air 29 °C at 06:00, setpoint 24 °C, learned rate 2.5 K per hour → needs 2 hours → start at 06:00 for 08:00. An earliest start limit stops it starting absurdly early after a long weekend. Optimum stop does the opposite — stopping a little early when the building can coast to the end of occupancy.

Overrides

  • Timed override for after-hours work: a BMS command or local button gives occupied mode for a fixed time (e.g. 2 hours), then reverts automatically. Log it — tenants are often billed for it.
  • Avoid permanent overrides; they are how plant ends up running all weekend (page 1.4).

Timers

TimerUse
On-delay (TON)Proving delays; alarm delays; stabilising before enabling a loop
Off-delay (TOF)Pump run-on after a chiller stops; fan run-on to clear an electric heater's heat
Minimum on / off timeStop compressors, fans and pumps short-cycling
Run-hour counterMaintenance scheduling; lead/lag rotation

More time-based logic

  • Staggered start: offset each AHU's start by a minute or two so the morning peak and the plant's starting currents are spread.
  • Lead/lag rotation: swap duty and standby pumps or fans by run-hours or weekly, so they wear evenly and the standby is known to work.
  • Unoccupied humidity control: in humid climates, an empty, closed building can reach mould-friendly humidity. Starting the AHU briefly when return humidity exceeds a limit (e.g. 70 %) protects the building.
  • Time synchronisation: all controllers take time from one NTP source; daylight-saving changes (where used) must be handled consistently.
Follow AHU-01

AHU-01: weekly schedule Monday–Saturday 08:00–19:00, Sunday off, the site's holiday calendar applied; optimum start with an earliest start of 06:30; timed override 2 h from the BMS or the floor's after-hours button; staggered start +0 min (AHU-02 +2 min, AHU-03 +4 min…); unoccupied humidity run when return RH exceeds 70 % for 30 minutes. The schedule lives in DDC-AHU-01.

⚒On site

  • Load the year's public holidays into the calendar before January — and check it every year.
  • Check where each schedule actually runs; schedules held only in the server stop working when it is down.
  • Review the override log monthly: frequent overrides mean the schedule does not match how the building is used.
  • After any time change (power loss, firmware update), check controller clocks against the NTP source.

AKey terms

Weekly schedule
Repeating on/off or mode times for each day.
Exception schedule
Schedule entry for a specific date or date range.
Holiday calendar
List of dates treated as holidays by schedules.
Optimum start
Starting plant at the time needed to reach setpoint by occupancy.
Timed override
Temporary occupied mode that reverts automatically.
On-delay / off-delay
Timers delaying switching on, or delaying switching off.
Minimum on/off time
Shortest run or rest time to prevent short-cycling.
Lead/lag rotation
Swapping duty and standby equipment to share wear.
Staggered start
Starting plant items at different times to limit peaks.

✓Check yourself

Try each one before opening the answer.

Fault scenario · what would you do?

On Republic Day the office was closed, but all AHUs ran from 08:00 to 19:00. The weekly schedules are correct. What was missing?

Weekly schedules do not know about holidays. The date must be in the calendar, and each schedule must reference that calendar as an exception.

  1. Why must schedules run in the controller rather than only on the server?

    Show answer
    So plant still starts and stops on time when the server or network is down.

  2. How does optimum start decide when to start?

    Show answer
    From the difference between room temperature and setpoint and the learned pull-down rate, within an earliest-start limit.

  3. Give one use each for an on-delay and an off-delay.

    Show answer
    On-delay: proving or alarm delays. Off-delay: pump run-on after a chiller stops.

  4. What is lead/lag rotation and why do it?

    Show answer
    Swapping duty and standby equipment (e.g. by run-hours) so wear is shared and the standby is known to work.

  5. Why might an AHU run in unoccupied hours in a humid climate?

    Show answer
    To bring down high humidity in the closed building and prevent mould and musty smells.
