In one line

Modbus is a simple ask-and-answer protocol: a client asks a device for numbered registers, the device replies with raw 16-bit numbers — and it is up to you to know what each number means.

?Why it matters

Modbus is everywhere: VFDs, energy meters, generators, UPSs, many chillers. It is easy to start with and easy to get subtly wrong — the device answers, but the values are nonsense because of an address offset, a data type or a byte order. Reading registers correctly is a core skill, practised in Lab 5.

⚙How it works

How Modbus works

  • One client (traditionally “master”) — the BMS controller or gateway — sends requests.
  • Each server (“slave”) — the VFD, meter — answers only when asked. Servers never talk on their own.
  • Modbus RTU runs on RS485 serial lines; each server has an address 1–247.
  • Modbus TCP carries the same requests over Ethernet (TCP port 502); a unit ID selects a device behind a gateway.

The four data tables

The off-by-one trap

Documentation often numbers registers from 1 with a table prefix — 40001 — but on the wire the first holding register is address 0. So “40001” = function 03, address 0; “40010” = address 9. Some tools and BMS drivers expect the documentation number, others the wire address. If every value looks like its neighbour's, you are off by one.

What a request looks like

Data types and byte order

Data typeRegistersExample
Unsigned 16-bit integer10 to 65,535 — e.g. frequency in 0.1 Hz: 425 = 42.5 Hz
Signed 16-bit integer1−32,768 to 32,767 — e.g. temperature in 0.1 °C: 65,486 read unsigned = −50 → −5.0 °C
32-bit integer2Energy totals — kWh
32-bit float (IEEE 754)2Many meters: 0x41B8 0x0000 = 23.0

32-bit values use two registers, and devices disagree on which comes first. The usual orders are ABCD (big-endian, high word first — the Modbus convention) and CDAB (word swapped). If a float reads as a huge or tiny nonsense number, try swapping the words.

When it goes wrong: exceptions and timeouts

ResponseMeaningUsual cause
No response (timeout)Nobody answeredWrong address, baud or parity; wiring; device off
Exception 01 — illegal functionDevice does not support that functionUsing 03 where the device needs 04 (or the reverse)
Exception 02 — illegal data addressRegister does not existOff-by-one, wrong map, reading past the end
Exception 03 — illegal data valueValue or quantity not allowedToo many registers in one request; out-of-range write

CRC errorsFrame corruptedNoise, termination, baud mismatch

Polling settings matter too: timeout (how long to wait), retries, and poll rate. A slow bus with many registers and a short poll interval never catches up.

Follow AHU-01

DDC-AHU-01 polls the VFD at address 1, 19200 8E1 every 5 seconds with function 03 for the first six holding registers. It scales frequency and current by 0.1, combines two registers for kWh, and alarms if the VFD stops answering for 60 seconds. If the link fails, AHU-01 keeps running on its hard-wired points.

⚒On site

  • Get the register map for the exact model and firmware, and note whether it numbers from 0 or 1.
  • Read a value you can verify on the device display first (e.g. frequency) to prove address, offset and scale.
  • Read the fewest registers you need, in blocks; avoid hundreds of single-register requests.
  • Only one client on an RTU bus. Two masters on one bus collide.

AKey terms

Client / server
Modbus roles: the client asks, the server answers (formerly master/slave).
Holding register
16-bit read/write value (4xxxx); read with function 03.
Input register
16-bit read-only value (3xxxx); read with function 04.
Coil / discrete input
1-bit read/write and read-only values.
Function code
Number identifying the request type, e.g. 03 read holding registers.
Exception code
Error reply from a server, e.g. 02 illegal data address.
Byte / word order
Order in which the bytes of a 32-bit value are sent (ABCD, CDAB…).
Unit ID
Field in Modbus TCP addressing a device behind a gateway.
CRC
Error-check field at the end of every RTU frame.

✓Check yourself

Try each one before opening the answer.

Fault scenario · what would you do?

An energy meter's map lists “voltage L1 = 30001, float32”. Reading function 04, address 1, 2 registers gives nonsense; the device display shows 231.4 V. What do you try first?

30001 is the first input register, which is address 0 on the wire. Reading from address 1 straddles two different values. If address 0 still gives nonsense, then try the other word order.
