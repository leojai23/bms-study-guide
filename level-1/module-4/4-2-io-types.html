Module 4 · Digital and Analog I/O

4.2 The four I/O types: DI, DO, AI, AO

Week 3 · Day 18About 10 minPage 2 of 6✓ Done
After this page you can
  • Classify any field signal as DI, DO, AI or AO.
  • Explain how each I/O type appears on the BMS and in BACnet.
  • Choose the right I/O for fans, dampers, valves and sensors.
  • Count the I/O for a plant item and size a controller with spare capacity.
Warm-up · 3 quick questions from earlier pages (2 min)
  1. How do you measure a 4–20 mA loop current safely?
    from 4.1 Electrical safety for BMS work
    Show answer
    Put the meter in series at a designed test point or openable terminal, or use a mA clamp — never connect a meter in current mode across a supply.
  2. What does a “running unexpectedly” alarm usually mean?
    from 3.8 Status devices: current switches and DP switches
    Show answer
    The equipment runs while the BMS commands it off — often a Hand switch, a welded contactor, or another system (e.g. fire control) starting it.
  3. Explain in three steps how a VFD makes a variable-frequency supply.
    from 3.7 Variable frequency drives (VFD)
    Show answer
    Rectifier converts AC to DC → DC bus stores and smooths it → inverter switches the DC to make AC at the required frequency.
In one line

Every hard-wired point is one of four types: DI and DO carry on/off states in and out of the controller; AI and AO carry a range of values in and out.

?Why it matters

The I/O type decides everything downstream: which controller terminal is used, what signal and cable are needed, how the point is configured and how it is shown on the screen. Classifying signals correctly is the first step of every point list, wiring diagram and controller selection — the basis of Labs 1 and 2.

⚙How it works

TypeDirectionSignalTypical examples
DI — digital inputInto the controllerContact open/closed (dry contact), sometimes a voltageRun status, fault, auto/manual, filter switch, fire signal, flow switch, pulses from meters
DO — digital outputOut of the controllerRelay or triac contactStart/stop, enable chiller, open/close damper, floating actuator open and close
AI — analogue inputInto the controllerResistance (NTC, PT1000), 0–10 V, 4–20 mATemperature, humidity, pressure, CO₂, flow, actuator feedback
AO — analogue outputOut of the controller0–10 V, 2–10 V, 4–20 mAValve position, damper position, VFD speed

Universal I/O

Many controllers have universal inputs (UI) — and some universal I/O (UIO) — that are set in software to the type and signal you need. They make design flexible, but every point must then be configured correctly: an NTC sensor on a UI set for 0–10 V will read nonsense.

How points look on the BMS

I/OBACnet objectShows asConfigured with
DIBinary Input (BI)Two state texts — Running/Stopped, Normal/AlarmNormal state (NO/NC), state texts, alarm state, delay
DOBinary Output (BO)Command On/Off with priorityMinimum on/off time, state texts, relinquish default
AIAnalog Input (AI)Value with units — 23.8 °CSensor type or range, scaling, units, offset, filter, limits
AOAnalog Output (AO)Value in % or unitsSignal range (0–10 / 2–10 V), min/max, relinquish default

Not every point is physical. Software points — setpoints, occupancy mode, calculated values such as mixed air fraction, alarm flags — live only in the controller program but appear on the BMS like any other point.

Counting I/O and sizing a controller

  1. List every device and its points (the point list — Lab 2).
  2. Count by type: DI, DO, AI, AO (and which inputs can share universal terminals).
  3. Add spare capacity — typically 10–20 % of each type — for changes during the project and later.
  4. Choose a controller (plus I/O modules if needed) that covers the totals, and check other limits: number of PID loops, trend memory, communication ports.
Follow AHU-01

AHU-01 has 1 DO, 5 DI, 5 AI and 3 AO = 14 hard-wired points, plus the Modbus link to the VFD and software points such as the 24 °C setpoint and the occupancy mode. Its 10 inputs can share universal inputs. With about 20 % spare, a controller with around 12 UI, 2 DO and 4 AO would do — sized properly in Lab 2.

⚒On site

  • When a reading is wrong, check the point configuration (type, range, units) before blaming the sensor.
  • Check the DI “normal” state: a filter switch configured the wrong way round shows an alarm when the filter is clean.
  • Look at the point's priority array or override flag before assuming an output is broken (Module 5).
  • Keep the I/O summary up to date — it is how the next engineer finds spare terminals.

AKey terms

DI
Digital input: an on/off state into the controller.
DO
Digital output: an on/off command from the controller.
AI
Analogue input: a range of values into the controller.
AO
Analogue output: a range of values from the controller.
Universal input (UI)
Input configurable as AI or DI and for different signal types.
Software (virtual) point
A point that exists only in the program — setpoints, modes, calculated values.
Normal state
The state of a DI that the BMS treats as normal (contact open or closed).
I/O summary
Count of all points by type, used to choose controllers.
Spare capacity
Unused I/O kept for future changes, typically 10–20 %.

✓Check yourself

Try each one before opening the answer.

Fault scenario · what would you do?

A new filter is fitted on AHU-02. The filter ΔP switch contact is open (clean filter), but the BMS shows “Filter dirty — ALARM”. What is wrong?

An open contact on a clean filter is correct. The BMS interprets the open contact as abnormal because the point is configured the wrong way round. Fix the configuration and test by closing the contact.

  1. Classify: valve position command, CO₂ reading, fan trip, chiller enable.

    Show answer
    Valve command = AO; CO₂ = AI; fan trip = DI; chiller enable = DO.

  2. What is a universal input?

    Show answer
    An input that can be configured in software as an AI or DI and for different signal types.

  3. Which BACnet object type represents a DI?

    Show answer
    Binary Input (BI).

  4. Give two examples of software points.

    Show answer
    Any two of: setpoints, occupancy mode, calculated values (e.g. fresh air fraction), alarm flags, schedules' outputs.

  5. Why add 10–20 % spare I/O?

    Show answer
    To allow for design changes during the project and future additions without new controllers.
