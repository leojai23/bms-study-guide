1.6 HVAC system integration

  • Compare hard-wired interfaces with high-level (protocol) interfaces.

Warm-up · 3 quick questions from earlier pages (2 min)
  1. Give three reasons for using interposing relays.
    from 1.5 BMS control panel architecture
    Show answer
    Isolation of the controller from 230 V circuits, higher contact rating, cheap and quick replacement, and a visible LED showing the command.
  2. Give two ways to reduce nuisance alarms.
    from 1.4 BMS server, workstation and operator interface
    Show answer
    Add time delays; suppress dependent alarms when plant is off by schedule; set sensible limits; review alarm counts regularly.
  3. What happens to AHU-01's outputs if DDC-AHU-01 loses power?
    from 1.3 The DDC controller and how it works
    Show answer
    They go to their fail-safe state: the fan start relay drops out so the fan stops, and spring-return actuators drive the valve and damper to their designed safe positions — for example the fresh air damper closes.
In one line

Integration means connecting equipment that has its own controller — chillers, VFDs, energy meters, VRF systems — to the BMS, so it can be monitored and commanded alongside everything else.

?Why it matters

Modern buildings are full of packaged equipment with built-in controls. One chiller can offer hundreds of values. Integration is how the BMS gets that information without hundreds of wires — and it is one of the most common, and most error-prone, jobs a BMS engineer does.

⚙How it works

Two ways to connect

Hard-wiredHigh-level interface (HLI)
HowOne pair of wires per signalOne communication cable carries many values

Common protocols

ProtocolWhere you will find it
BACnet (IP and MS/TP)The main open BMS protocol: controllers, chillers, VRF gateways. Module 5.
Modbus (RTU and TCP)VFDs, energy meters, generators, UPS, many chillers. Module 5.
M-BusHeat (BTU) and water meters, especially in Europe.
KNX, DALILighting and room control.
LonWorksOlder installations.
OPC UA, MQTT, web APIsLinks to IT systems, analytics and cloud platforms.

When two systems speak different protocols, a gateway (protocol converter) translates — for example from a VRF manufacturer's own protocol to BACnet/IP.

The rule of thumb

Hard-wire what must work, integrate what you want to know

Commands and status that the plant depends on — enable, start/stop, run status, common fault, fire shutdown — are hard-wired. Detail — internal temperatures, kW, alarm codes, run-hours — comes over the high-level interface. If communication fails, the plant still works and the BMS still knows whether it is running.

Integration step by step

  1. Get the documents — the device's register map (Modbus) or PICS and object list (BACnet), and the communication settings it supports.
  2. Agree the interface — an interface (responsibility) matrix lists which points are needed, read or write, and who supplies the cable, gateway and configuration.
  3. Set the communication parameters on both sides — protocol, address or device ID, baud rate, IP settings (Module 5).
  4. Connect and discover — wire the bus or network and check the BMS can see the device.
  5. Map the points — create a BMS point for each register or object, with the correct scaling and units.
  6. Test point to point — compare every value on the BMS with the device's own display, and test every write (change the setpoint, see it change on the chiller).
  7. Finish the front end — add the integrated points to graphics, alarms and trends.

Follow AHU-01

AHU-01's VFD uses both methods. Hard-wired: start/stop (DO), run status and fault (DI), speed reference (AO). Modbus RTU: output frequency, motor current, kW, kWh and the last fault code. If the Modbus link fails, AHU-01 keeps running and the BMS still knows whether the fan is on.

⚒On site

  • Get the register map or object list for the exact model and firmware — tables change between versions.
  • Check the scaling of every value: a Modbus register reading 2415 might mean 241.5 V or 24.15 Hz.
  • Test writes carefully on live plant. Changing a chiller setpoint or a VFD parameter has real effects.
  • Keep a table of every integrated device: address or device ID, baud rate, parity, IP address.
  • Agree in writing who configures the third-party side. Many integration delays are spent waiting for another vendor's engineer.

✓Check yourself

Try each one before opening the answer.

Fault scenario · what would you do?

A chiller is integrated over Modbus. The BMS shows the chilled water supply temperature as 70 °C, while the chiller's own display shows 7.0 °C. What is wrong?

The value is exactly ten times too large and otherwise correct, so communication is fine. The register holds tenths of a degree; apply a scale of 0.1 to the BMS point. A baud-rate error would stop communication completely.

  1. What is the difference between a hard-wired interface and a high-level interface?

    Show answer
    Hard-wired uses one pair of wires per signal — few values, very reliable. A high-level interface uses one communication cable and a protocol to carry many values — cheap per value, but it depends on communication settings and software.

  2. Which AHU-01 VFD signals are hard-wired, and why?

    Show answer
    Start/stop, run status, fault and speed reference — so the fan can be controlled and monitored even if the Modbus link fails.

  3. What is a gateway used for?

    Show answer
    To translate between two different protocols, e.g. a manufacturer's own protocol to BACnet/IP.

  4. List the seven steps of integrating a device.

    Show answer
    Get documents → agree the interface → set communication parameters → connect and discover → map points → point-to-point test → graphics, alarms and trends.

  5. Why must you be careful when testing writes on live plant?

    Show answer
    Writing a setpoint or parameter changes how real equipment runs; a mistake can trip plant or affect occupants.
