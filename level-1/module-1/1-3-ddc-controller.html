1.3 The DDC controller and how it works

In one line

A DDC (Direct Digital Control) controller is a small industrial computer that reads its inputs, runs a control program and writes its outputs — in a continuous loop, typically once a second or faster.

?Why it matters

Every point on a BMS starts or ends at a controller terminal. When you understand how the controller sees the world — as numbers read and written on every cycle — most things you see on site make sense: why readings are smoothed, why an output “won't move”, and what happens when the power or the network drops.

⚙How it works

Why “direct digital”?

Before DDC, buildings used pneumatic (compressed-air) or electronic analogue controllers. Each control loop needed its own device, and the logic was fixed by the hardware. With DDC, a digital processor makes the control decisions directly in software. One controller can run many loops, the logic is changed by editing the program, and every value can be shared over the network and shown on the BMS.

The scan cycle

  1. Read inputs. The controller samples every input terminal: the resistance of a temperature sensor, a voltage, a current, an open or closed contact.
  2. Convert. Raw readings become engineering units using each input's configuration — for example 10.5 kΩ from an NTC sensor becomes 23.8 °C, and 12 mA becomes 250 Pa. Filtering smooths out electrical noise.
  3. Run the program. The logic runs: compare values with setpoints, calculate PID loops, check interlocks and alarms, follow the schedule.
  4. Write outputs. The results go to the output terminals: a relay closes, a valve gets a new 0–10 V signal.
  5. Communicate. Share values with other controllers and the server, and accept operator commands such as a setpoint change.

Then it starts again. A cycle typically takes between a tenth of a second and about one second. That is fast enough for HVAC, where temperatures change over minutes, not milliseconds.

Standalone operation and fail-safe positions

A DDC controller must not depend on the server to do its job. Its program, setpoints and schedule are stored locally. If a value it receives over the network — such as the outdoor temperature from another controller — stops updating, a good program detects this and switches to a sensible fallback value.

If the controller itself loses power, outputs go to their fail-safe state: relays drop out (so fans stop) and spring-return actuators drive valves and dampers to a chosen safe position — for example the fresh air damper closes. Choosing these positions is part of the design.

Follow AHU-01

DDC-AHU-01 runs AHU-01. On every scan it reads the return air temperature (AI), compares it with the 24 °C setpoint, runs a PID loop and writes a new CHW valve position (AO). It also checks that the fan's run status (DI) follows the start command (DO) — if the fan does not prove running within about 30 seconds, it raises a fan fail alarm and stops the fan.

⚒On site

  • A healthy controller usually shows: power LED on, a “run” or heartbeat LED blinking, and communication LEDs flickering. Learn what the LEDs mean on the brand you work with.
  • Check the controller's own reading (local display or service tool) before blaming the BMS server.
  • Back up the controller program and database before any change, and again after commissioning.
  • Leave spare capacity: a good panel design keeps around 10–20 % spare I/O for future changes.
  • Never connect 230 V to an input or output rated for 24 V — it destroys the I/O circuit instantly.
  • When an output “won't respond”, look for an override first: on the BMS, on the controller, or a hand/auto switch in the panel.

AKey terms

DDC
Direct Digital Control: a digital processor makes the control decisions in software.
Scan cycle
The repeating loop of read inputs → convert → run program → write outputs → communicate.
ADC / DAC
Converters between electrical signals and numbers: analogue-to-digital (inputs) and digital-to-analogue (outputs).
Universal input (UI)
An input that can be configured in software as analogue or digital.
Plant controller
A freely programmable controller for complex plant such as AHUs.
ASC
Application-specific controller with a pre-loaded program, used for FCUs, VAV boxes and similar.
Fail-safe position
The state an output goes to when power or control is lost.
Override
A manual command that replaces the program's output until it is released.
Firmware
The controller's built-in operating software, separate from the application program.

Fault scenario · what would you do?

After a weekend power cut, DDC-AHU-01 is running again, but AHU-01 now starts at 03:00 instead of 08:00 every day. The schedule settings look correct. What is the most likely cause?

The schedule is right but runs at the wrong time, so the controller's clock is wrong. Check the clock's backup battery and set up network time synchronisation from the server.

  1. Put the five steps of the scan cycle in order.

    Show answer
    Read inputs → convert to engineering units → run the program → write outputs → communicate. Then repeat.

  2. What does the ADC do in a controller?

    Show answer
    The analogue-to-digital converter turns an electrical input — resistance, voltage or current — into a number the processor can use.

  3. What is the difference between a plant controller and an ASC?

    Show answer
    A plant controller is freely programmable and used for complex plant such as AHUs. An ASC runs a pre-loaded application for a standard unit such as an FCU or VAV box; you only set options and parameters.

  4. What happens to AHU-01's outputs if DDC-AHU-01 loses power?

    Show answer
    They go to their fail-safe state: the fan start relay drops out so the fan stops, and spring-return actuators drive the valve and damper to their designed safe positions — for example the fresh air damper closes.

  5. Name three things a controller stores in its memory.

    Show answer
    The program, settings such as setpoints and schedules, and recent trend and alarm data.
