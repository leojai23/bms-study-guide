1.2 BMS architecture: field, automation and management levels

Warm-up · 1 quick question from earlier pages (2 min)
  1. Why is the fire alarm system kept independent of the BMS?
    from 1.1 What is a BMS?
    Show answer
    Life-safety functions must work even if the BMS, its network or its software fails. Fire systems have their own approved controls; the BMS only receives signals for monitoring, and safety actions such as AHU shutdown are hard-wired.
In one line

A BMS is built in three layers: field devices measure and act, automation controllers run the control logic, and the management level gives people a window into the whole building.

?Why it matters

When something goes wrong, the first useful question is which level is the problem at? A wrong temperature on screen could be a faulty sensor (field), a configuration mistake (automation) or a stale screen (management). Thinking in levels turns a vague complaint into a short list of checks.

The three levels are described in the international standard for building automation, ISO 16484, so every manufacturer's system follows the same basic pattern — even when the product names differ.

⚙How it works

Field level — the senses and muscles

Everything that physically touches the building: sensors (temperature, humidity, pressure, CO₂), actuators (valves, dampers), switches, relays and drives. Most field devices are wired straight to a controller's inputs and outputs — this is hard-wired I/O.

Smarter field devices — VFDs, energy meters, small room controllers — talk to the controller over a field bus, usually an RS485 cable running BACnet MS/TP or Modbus RTU.

Automation level — the brains

DDC controllers read the field devices, run the control program and drive the outputs. Each controller looks after one plant item or one area — one AHU, a group of FCUs, the chiller plant.

Larger systems add a supervisory controller (also called a network controller or building controller). It usually controls no equipment itself. Instead it:

  • collects data from the field controllers below it,
  • routes messages between the RS485 field bus and the IP network,
  • runs building-wide schedules and shares values such as outdoor temperature,
  • stores trends and alarms locally while the server is unavailable.

Management level — the window

The BMS server and the operator workstations. This is where people view graphics, acknowledge alarms, change setpoints and schedules, look at trends and print reports. The server also keeps long-term history and connects to other systems such as energy dashboards and maintenance software.

The golden rule: control lives in the controller

Remember

The server is a window, not the brain. If the server or the network goes down, every DDC controller must keep running its plant with its own program, setpoints and schedule. Operators lose visibility, but the building keeps working. This is called standalone operation, and it is the main reason for the layered design.

If this fails……this still works…and this is lost
BMS serverAll controllers run normallyGraphics, central alarms, long-term trends (controllers may buffer some)

Modern systems: the levels are flattening

Older systems had strict layers joined by proprietary networks. Today many controllers sit directly on the IP network, and some field devices (smart actuators, wireless sensors) talk IP too. The three-level model is still the right way to think: even when everything shares one network, each device still does a field, automation or management job.

⚒On site

  • For any complaint, decide the level first: is the field device wrong, the controller logic wrong, or only the screen?
  • Compare the value on the BMS screen with the value at the controller (local display or service tool). If they match, look at the field device or the logic; if not, look at communication or the server.
  • Keep a copy of the network riser diagram. It shows which controller sits on which network and is the map for every communication fault.
  • Ask which plant must keep running without the server. Its schedules and setpoints must live in the controller.

AKey terms

Field level
Sensors, actuators and other devices that measure and act on the building.
Automation level
DDC and supervisory controllers that run the control logic.
Management level
Servers, workstations and clients used by people to view and manage the system.
Supervisory controller
A controller that manages a group of field controllers, routes between networks and stores data locally.
Field bus
A communication cable (usually RS485) linking controllers and smart field devices.
Hard-wired I/O
Field devices wired directly to controller input and output terminals.
Standalone operation
A controller running its plant on its own when the server or network is unavailable.
Network riser diagram
Drawing showing every controller and how they connect, floor by floor.

✓Check yourself

Try each one before opening the answer.

Fault scenario · what would you do?

The 5th-floor graphics show “---” for every value. Staff on the 5th floor say it is comfortable, and you can hear the AHU running. Where is the fault most likely?

The floor is comfortable and the AHU runs, so the sensors and controllers are working. Only visibility is lost, which points to the link between the floor and the server.

  1. Name the three levels of a BMS and give one device at each.

    Show answer
    Management — BMS server or workstation. Automation — DDC plant controller or supervisory controller. Field — temperature sensor, valve actuator, VFD.

  2. What does a supervisory controller do?

    Show answer
    It manages a group of field controllers: collects their data, routes messages between the field bus and the IP network, runs shared schedules and values, and buffers trends and alarms if the server is down. It usually has little or no plant I/O.

  3. The BMS server is switched off for maintenance. What happens to AHU-01?

    Show answer
    Nothing changes in its operation. DDC-AHU-01 keeps running its program, setpoints and schedule. Operators cannot see the graphic or receive central alarms until the server is back.

  4. Why might a VFD be connected over a field bus as well as hard-wired?

    Show answer
    The field bus gives many extra values — frequency, current, kW, energy, fault codes — for the cost of one cable. The critical start/stop and status are still hard-wired so the fan works if communication fails.

  5. Which standard describes the three-level model for building automation?

    Show answer
    ISO 16484.
